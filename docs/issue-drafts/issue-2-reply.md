ご報告ありがとうございます。原因の特定まで含め、まったくご指摘のとおりでした。

**原因**: SwiftPM が生成する `Bundle.module` のアクセサが `.app` 直下と開発機の絶対パスしか探さず、`make-app.sh` が置く `Contents/Resources/` を見ていませんでした。開発機では絶対パスのフォールバックが効くため、配布前の確認をすり抜けていました。手元でもフォールバックを隠すと同じメッセージで落ちることを確認しています。

**修正（v1.6.1）**:
- `Bundle.main.resourceURL` 配下を最優先で解決するアクセサ（`AppResources.bundle`）を用意し、`Bundle.module` の直接使用をやめました（提案いただいた1つ目の案です）
- 再発防止として、`.app` を組み立てるたびに **フォールバックを使わず `Contents/Resources` から実際に文字列と音を引けるか**をアプリ自身に検証させ、失敗したら組み立てを中断するようにしました（リリース工程・CI とも）。あわせて `Bundle.module` の直接使用をビルド時に検知して止めます

v1.6.0 は使用量の読み込み前に落ちるため自動アップデートが走りません。お手数ですが v1.6.1 の zip または Homebrew で入れ直してください。回避策として置いた `.app` 直下のコピーは、v1.6.1 では不要です（署名の警告も出なくなります）。
