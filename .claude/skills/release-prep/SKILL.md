# リリースの準備

作業が終わったら、次の順に進めて止まる。**公開は絶対にしない。**

1. **状態の確認**: 変更をコミットし、前回のタグ（`git describe --tags --abbrev=0`）を確認する。
2. **コードレビュー**: `/code-review high` で前回のタグ以降の全差分を見る。指摘は未検証の候補として扱い、コードや実測で確かめてから直す。見送る指摘は理由を残す。修正したらテストを通常時と `CLAUDEBAR_FORCE_LEGACY=1` の両方で通し、修正の差分に新しい問題がないようレビューを繰り返す。
3. **リリースノートの下書き**: `docs/release-notes/v<バージョン>.md` を、前回のタグ以降の全コミット（`git log <タグ>..HEAD`）から書く。利用者に見える変更を先に書き、未確認のことを確認済みのように書かない。
4. **README の最新化**: `README.md` と `README.en.md` を今回の変更に合わせて同時に更新する（機能、動作環境、権限、ビルド手順）。
5. **CI**: 許可があれば push し、`gh run` で成功を確認する。
6. **止まって報告**: レビューの結果、リリースノートの内容、未確認の項目を報告し、次の手順を伝えて止まる。
   - 手動の確認: `docs/RELEASE_CHECKLIST.md`
   - 本人がターミナルで実行: `./scripts/preflight.sh <バージョン>`、`./scripts/release.sh <バージョン>`

## してはいけないこと

- `scripts/release.sh` の実行、タグの作成、`main` への push やマージを、明示の指示なしに行うこと
- `preflight.sh` と `release.sh` の確認入力を、本人に代わって行うこと、または回避すること
